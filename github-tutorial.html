1. GitHub 简介

GitHub 是全球最大的代码托管平台，基于 Git 版本控制系统构建。截至 2024 年，GitHub 拥有超过 1 亿开发者用户、4 亿多个代码仓库，是开源协作的核心枢纽。

核心功能一览

代码仓库

托管你的项目源码，支持私有与公开仓库。

分支管理

多人并行开发，互不干扰，再合并到主分支。

Pull Request

代码评审与合并请求，团队协作的核心机制。

Issues

追踪 Bug、任务与功能需求，支持标签和里程碑。

GitHub Actions

CI/CD 自动化流水线，自动构建、测试、部署。

GitHub Pages

免费托管静态网站，直接从仓库部署。

2. 注册 GitHub 账户

访问 github.com，点击右上角 Sign up 开始注册。

🔒 https://github.com/signup

Welcome to GitHub!

you@example.com
••••••••••••••
your-username

填写邮箱地址

使用一个长期可用的邮箱（推荐 Gmail / Outlook），用于接收验证邮件和通知。

设置高强度密码

至少 15 个字符，或包含数字 + 小写字母至少 8 位。建议使用密码管理器。

选择用户名

用户名将出现在你所有的仓库 URL 中（如 github.com/你的用户名），建议使用英文小写、简短易记。

验证邮箱并完成 2FA

查收邮箱验证码完成注册。强烈建议开启两步验证（2FA），可用 Authenticator app 或硬件密钥。

提示免费账户即可创建无限多的公开和私有仓库，对个人开发者已足够使用。

3. 安装 Git 客户端

Git 是 GitHub 背后的版本控制系统。要在本地与 GitHub 交互，需先安装 Git。

各平台安装方法

操作系统安装命令 / 方式验证
Windows访问 git-scm.com 下载安装包git --version
macOSbrew install git 或 Xcode Command Line Toolsgit --version
Ubuntu/Debiansudo apt install gitgit --version
CentOS/RHELsudo yum install gitgit --version

首次配置

安装完成后，配置你的 Git 用户信息（这些信息会出现在每次 commit 记录中）：

~ / bash 
$ git config --global user.name "Your Name"
$ git config --global user.email "you@example.com"
$ git config --global init.defaultBranch main
# 查看当前配置
$ git config --list
user.name=Your Name
user.email=you@example.com
init.defaultbranch=main

配置 SSH 密钥（推荐）

使用 SSH 密钥可以免去每次 push 输入密码的麻烦：

~ / bash 
# 1. 生成 SSH 密钥（一直回车即可）
$ ssh-keygen -t ed25519 -C "you@example.com"

# 2. 启动 ssh-agent 并添加密钥
$ eval "$(ssh-agent -s)"
$ ssh-add ~/.ssh/id_ed25519

# 3. 复制公钥内容（粘贴到 GitHub）
$ cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... you@example.com

# 4. 测试连接
$ ssh -T git@github.com
Hi username! You've successfully authenticated.

将公钥添加到 GitHub：Settings → SSH and GPG keys → New SSH key，粘贴 id_ed25519.pub 内容并保存。

5. Git 基础命令

掌握以下命令，可应对 90% 的日常使用场景。

Git 工作流核心概念

克隆已有仓库

~ / bash 
# 使用 HTTPS
$ git clone https://github.com/username/my-first-project.git

# 使用 SSH（推荐）
$ git clone git@github.com:username/my-first-project.git

Cloning into 'my-first-project'...
remote: Enumerating objects: 42, done.
remote: Counting objects: 100% (42/42), done.
Receiving objects: 100% (42/42), 5.21 KiB | 5.21 MiB/s, done.

$ cd my-first-project

日常工作流：add → commit → push

~/my-first-project 
# 1. 查看当前状态
$ git status
On branch main
Changes not staged for commit:
  modified:   README.md
Untracked files:
  hello.py

# 2. 添加文件到暂存区
$ git add README.md hello.py
# 或一次性添加所有变更
$ git add .

# 3. 提交到本地仓库
$ git commit -m "feat: add hello.py and update README"
[main 7f3a9b1] feat: add hello.py and update README
 2 files changed, 25 insertions(+), 3 deletions(-)

# 4. 推送到远程
$ git push origin main
Enumerating objects: 5, done.
Writing objects: 100% (3/3), 312 bytes | 312.00 KiB/s, done.
To github.com:username/my-first-project.git
   3a8d72f..7f3a9b1  main -> main

常用命令速查表

命令用途
git init把当前目录变成 Git 仓库
git clone <url>克隆远程仓库到本地
git status查看工作区与暂存区状态
git diff查看尚未暂存的修改
git add <file>添加文件到暂存区
git commit -m "msg"提交暂存区到本地仓库
git log --oneline查看提交历史
git push推送本地提交到远程
git pull拉取并合并远程更新
git fetch仅下载远程更新，不合并
git reset --soft HEAD~1撤销最近一次提交，保留改动
git stash临时保存当前改动
注意提交信息应清晰描述本次改动。推荐使用约定式提交格式：feat:（新功能）、fix:（修 bug）、docs:（文档）、refactor:（重构）。

6. 分支与合并

分支（Branch）允许你脱离主线进行开发，完成后再合并回去。这是团队协作和实验性开发的基石。

分支操作命令

~/my-first-project 
# 查看所有分支（* 表示当前所在分支）
$ git branch
* main
  develop

# 创建并切换到新分支
$ git checkout -b feature/login
# 或使用新语法
$ git switch -c feature/login

# 在分支上做修改并提交
$ echo "login feature" > login.txt
$ git add login.txt && git commit -m "feat: add login feature"

# 推送新分支到远程
$ git push -u origin feature/login

# 切回主分支
$ git switch main

# 合并 feature 分支到当前分支
$ git merge feature/login

# 删除已合并的分支
$ git branch -d feature/login
$ git push origin --delete feature/login

处理合并冲突

当两个分支修改了同一文件的同一行，合并时会出现冲突。Git 会在文件中标记冲突位置：

<<<<<<< HEAD
console.log("Hello from main branch");
=======
console.log("Hello from feature branch");
>>>>>>> feature/login

手动编辑保留所需内容，删除标记，然后 git add + git commit 即可完成合并。

提交 PR 的标准流程

Fork 仓库（仅限协作他人项目时）

在 GitHub 网页点击右上角 Fork，把仓库复制一份到你自己的账户下。

克隆 Fork 后的仓库并创建新分支

git clone + git switch -c feature/xxx

开发、提交、推送

正常 commit & push 到你 Fork 仓库的分支。

在 GitHub 网页点击 "Compare & pull request"

填写清晰的标题与描述，关联相关 Issue（如 Closes #38）。

等待审查、根据反馈修改、被合并 🎉

审查者可能给出修改建议，你只需在同一分支继续 push 即可，PR 会自动更新。

8. Issues 问题追踪

Issues 是 GitHub 内置的轻量级工单系统，用于跟踪 Bug、需求、讨论等。

🔒 https://github.com/your-username/my-first-project/issues/38
⊙ Open #38 opened 3 days ago by reporter-user

[Bug] 登录按钮在 Safari 浏览器上无响应

bug browser-compat priority: high
reporter-user commented 3 days ago

复现步骤：

  1. 在 Safari 17 打开 /login 页面
  2. 输入用户名和密码
  3. 点击"登录"按钮

预期： 跳转到首页

实际： 按钮无反应，控制台报错 Uncaught TypeError: ...

编写好 Issue 的要点

  • 清晰的标题：一句话概括问题，如 "[Bug] 登录按钮在 Safari 上无响应"
  • 复现步骤：让别人能照着重现问题
  • 期望 vs 实际行为：明确哪里出了差错
  • 环境信息：浏览器版本、操作系统、依赖版本
  • 截图 / 日志：一图胜千言
  • 标签（Labels）：bug / enhancement / question / good first issue

9. 团队协作

添加协作者

进入仓库 Settings → Collaborators，通过用户名或邮箱邀请他人。被邀请者接受后即可拥有 push 权限。

Code Owners

在 .github/CODEOWNERS 文件中定义关键文件的所有者，PR 修改这些文件时会自动请求他们审查：

# 全局默认所有者
*       @team-lead

# 前端代码
/src/frontend/  @frontend-team

# 后端 API
/src/api/       @backend-team @security-team

# 文档
*.md            @docs-team

保护分支（Branch Protection）

对 main 分支启用保护规则，防止直接 push、强制要求 PR 与代码审查：

  • ✅ Require a pull request before merging
  • ✅ Require approvals (至少 1 人审批)
  • ✅ Require status checks to pass (CI 必须通过)
  • ✅ Require conversation resolution before merging
  • ✅ Do not allow bypassing the above settings

10. GitHub Actions 自动化

GitHub Actions 是内置的 CI/CD 平台，让你在代码推送、PR 提交、定时任务等事件触发时自动执行任务。

第一个 Workflow 示例

在仓库中创建 .github/workflows/ci.yml：

name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run linter
        run: npm run lint

      - name: Run tests
        run: npm test

      - name: Build
        run: npm run build

常见用途

🧪 持续集成

每次 push 自动跑测试、检查代码风格。

🚀 自动部署

合并到 main 后自动部署到 Vercel、AWS、Cloudflare 等。

📦 发布版本

打 tag 时自动构建二进制并创建 Release。

🤖 自动化任务

定期清理 Issue、发送通知、依赖更新。
